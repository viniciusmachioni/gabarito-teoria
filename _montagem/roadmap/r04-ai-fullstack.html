R4

AI + Full Stack Integration

~8h · a chamada ao modelo é a parte fácil; o difícil é tudo em volta dela

Uma vaga de Frontend/Design Engineer com foco em IA não te pede pra treinar modelo — pede pra entregar o produto em volta dele: quem pode chamar (auth), como a resposta chega na tela (streaming), onde mora o arquivo que o usuário mandou (upload e storage), o que acontece quando o trabalho demora mais que um request (fila), onde a saída fica guardada (Postgres) e como provar que tudo isso funciona sem gastar cota de API em cada teste. A boa notícia: o Gabarita e o Ally AI já fazem boa parte disso. Esta página dá nome ao que você fez, aponta o arquivo e mostra o que falta — principalmente streaming, embeddings/pgvector e Playwright.

Onde estudar (grátis)

  • Next.js — route.js (Route Handlers)
    A referência do arquivo que vira endpoint no App Router: métodos, params como promessa, cookies, webhooks e a seção de Streaming com ReadableStream puro.
    Ler trechos · ~20 minLeia Parameters, Streaming, Request Body FormData, Webhooks e Segment Config. Pule Cookies/Headers se já usa.
    nextjs.org · oficial
  • Gemini API — Embeddings
    Os dois projetos já usam @google/genai; este é o mesmo SDK gerando vetores com embedContent — o primeiro passo de qualquer RAG ou busca semântica.
    Ler trechos · ~20 minLeia o exemplo em JavaScript, task types, controle de dimensão e casos de uso. Pule a parte de multimodal se o seu caso é só texto.
    ai.google.dev · oficial
  • pgvector — README
    A extensão que transforma o Postgres que você já tem num banco vetorial: tipo vector, operadores de distância, HNSW/IVFFlat, filtro com índice aproximado.
    Ler trechos · ~30 minLeia Getting Started, Querying, Indexing (HNSW e IVFFlat) e Filtering. Half-precision, binary e sparse são consulta pra quando escala virar problema.
    github.com · oficial
  • Amazon S3 — Uploading objects with presigned URLs
    Como deixar o navegador mandar o arquivo direto pro bucket, sem credencial AWS e sem passar o corpo pelo seu servidor. O mesmo vale pro R2, que fala a API do S3.
    Ler trechos · ~15 minLeia a introdução, a parte de SDK (o exemplo é Python, mas o conceito é o mesmo no @aws-sdk) e o troubleshooting de SignatureDoesNotMatch. Pule o Visual Studio.
    docs.aws.amazon.com · oficial
  • AI SDK — Testing
    Modelos falsos (MockLanguageModel) e simulateReadableStream: a referência de como testar streaming e saída estruturada sem chamar o modelo de verdade.
    Ler inteiro · ~15 minPágina curta, quase só código. Mesmo sem usar o AI SDK, o exemplo de Route Handler que devolve SSE simulado serve pra qualquer front que consome stream.
    ai-sdk.dev · oficial
  • Playwright — Mock APIs
    page.route + route.fulfill, editar resposta real, gravar/reproduzir HAR e mockar WebSocket — tudo o que um E2E de fluxo de IA precisa pra ser rápido e reprodutível.
    Ler inteiro · ~15 minPágina curta. A seção de WebSocket é exatamente o caso do saldo de créditos do Ally AI.
    playwright.dev · oficial

No seu código: Gabarita e Ally AI

Onde cada item do roadmap já aparece · caminhos relativos à raiz de cada projeto

App de IA completo: React/Next.js + Node Gabarita: usado Ally AI: usado

Gabarita — Next.js full stack (Server Actions, Route Handlers, RSC lendo direto do Prisma) mais um worker Node separado que consome a fila. São dois processos a partir do mesmo código: worker/index.ts importa ../src/lib/... e registra três consumidores (L59–62: extract-document, generate-questions, caderno-key-points), com startWithRetry (L32–47) pra sobreviver ao banco subindo depois do worker e desligamento limpo em SIGTERM (L65–70).

Ally AI — o outro desenho: Next.js 16 como cliente de uma API Express 5, num monorepo com tipos compartilhados (packages/types). O caminho de uma auditoria: apps/web/src/lib/api.ts (axios com withCredentials, L4–7) → apps/api/src/controllers/AuditController.ts (analyze, L13–63) → runAudit (Puppeteer + axe) → Gemini → prisma.analysis.create (L39–46) → JSON de volta.

Detalhe que mostra maturidade: em apps/api/src/index.ts o webhook do Stripe é registrado com express.raw (L43–47) antes do express.json() (L49) — a assinatura do webhook é calculada sobre o corpo cru, e o parser JSON destruiria isso.

Autenticação, streaming, upload e processamento assíncrono Gabarita: parcial Ally AI: parcial

Autenticação — os dois têm. Gabarita: Auth.js (next-auth v5) com Credentials + Google em src/lib/auth/index.ts; o rate limit de login mora dentro do authorize (L24–32), porque POST /api/auth/callback/credentials aceita request direto sem passar pela tela. Ally AI: argon2 + JWT de 7 dias em cookie httpOnly/secure/sameSite=none (AuthController.ts L89–107), e o mesmo cookie autentica o WebSocket: io.use em index.ts L55–87 lê ally-ai.token, verifica o JWT e põe o socket na sala do usuário (L89–97).

Upload — só o Gabarita. src/app/(app)/ingestao/actions.ts L16–56: Server Action recebe o PDF (bodySizeLimit: "25mb" em next.config.ts L13), valida tipo/tamanho, salva com getStorage() e enfileira EXTRACT_DOCUMENT. Atenção ao detalhe honesto: o PDF vai pra disco local (src/lib/storage/index.ts, UPLOAD_DIR), não pro R2 — web e worker precisam do mesmo volume, o que amarra o deploy.

const buffer = Buffer.from(await file.arrayBuffer());
const storagePath = await getStorage().save(buffer, file.name);
// ...
const queue = await getQueue();
await queue.enqueue(EXTRACT_DOCUMENT, { docId: doc.id });

Assíncrono — os dois, de jeitos diferentes. Gabarita: fila durável no próprio Postgres com pg-boss (src/lib/queue/pg-boss.ts L19–43), com prazo de 2h só pra extração (L16) depois que duas provas foram mortas no meio pelo default de 15 min; e after() do Next pra gerar explicação depois que a resposta HTTP saiu (src/lib/study/explain-prefetch.ts L18–30). Ally AI: semáforo em memória com fila FIFO e recusa imediata quando lota (apps/api/src/services/auditQueue.ts L14–44) — controla concorrência, mas a auditoria ainda roda dentro do request (AuditController.ts L37). Evento de volta pro cliente: webhook do Stripe → io.to(userId).emit("credits_updated") (WebhookController.ts L42) → hook apps/web/src/hooks/useCreditSocket.ts com cleanup no unmount (L29–32).

Streaming de LLM — nenhum dos dois. Não há generateContentStream, SSE nem leitura de stream de modelo. O Gabarita resolve a espera com after() + polling com desistência (question-runner.tsx L117–122: refresh em 3s, 9s e 21s, desiste em 23s). O mais perto de stream que existe é lerAteOTeto em src/lib/diretrizes/url-segura.ts (L133–149): lê o corpo de um download em pedaços com getReader() e cancela ao passar do teto de bytes — o mesmo laço que o cliente usaria pra consumir tokens.

LLM + PostgreSQL + serviços cloud Gabarita: parcial Ally AI: parcial

Saída da IA guardada com consistência. Gabarita: src/lib/study/explain.ts — trava atômica com updateMany condicional (L66–74) pra duas abas não pagarem duas chamadas, e motivos + marca de “pronta” gravados na mesma $transaction (L105–117). Ally AI: o relatório enriquecido pela IA vai inteiro numa coluna results Json (JSONB) do modelo Analysis (apps/api/prisma/schema.prisma L21–32), e o crédito é reservado com updateMany condicional e devolvido em qualquer falha (AuditController.ts L27–35, L53, L66–75).

Grounding sem vetor. Gabarita: fetchStyleReferences (src/lib/generation/generate-question.ts L5–24) busca até 3 questões aprovadas do mesmo tema como referência de estilo — recuperação por filtro relacional, não por similaridade; e citacaoVerificada (src/lib/diretrizes/citacao.ts L20–24) só publica o resumo se a citação existir palavra por palavra no texto da fonte. Ally AI: o modelo recebe os achados do axe (fatos determinísticos), não o site inteiro.

Cloud storage — Gabarita. src/lib/storage/image-storage-r2.ts usa @aws-sdk/client-s3 apontado pro Cloudflare R2 (L18–31), com timeout explícito (L29) depois de um PUT pendurado ~15 min ter vencido o job de extração; image-storage.ts L6–13 escolhe R2, Vercel Blob ou disco por variável de ambiente.

Lacuna nos dois: nenhum embedding, nenhum vector no schema, nenhum pgvector, nenhuma busca semântica. É o item do roadmap com maior distância entre o que você tem e o que vai ser perguntado.

Munição da sua entrevista · a explicação que nunca bloqueia a tela (Gabarita)

“A revelação de certo/errado chegou a levar 15 segundos porque a explicação da IA estava no caminho do render. Tirei a IA do caminho crítico: a página agenda a geração com after() assim que a questão abre, então ela fica pronta enquanto o aluno lê (explain-prefetch.ts). Uma trava atômica no Postgres — updateMany condicional, não select seguido de update — garante que duas abas não paguem duas chamadas (explain.ts L66–74). No cliente, polling com desistência em 23 segundos e um fallback explícito, testado com fake timers. O próximo passo é trocar o polling por streaming.”

Por que isso importa: é uma história de full stack de IA inteira — latência percebida, custo de cota, concorrência no banco, estado de erro na UI e teste determinístico — num fluxo só. E terminar com “o próximo passo é streaming” mostra que você sabe onde está o limite da solução atual.

Responda em voz alta · só depois abra o gabarito
  1. Por que a auditoria do Ally AI rodar dentro do request HTTP é um problema, mesmo com o semáforo de concorrência?
    ver resposta

    O semáforo limita quantas rodam ao mesmo tempo, mas não muda onde elas vivem: dentro de um request que pode levar dezenas de segundos. Isso obriga timeout alto na plataforma, prende uma conexão aberta, e um restart ou deploy no meio perde a auditoria (o crédito é devolvido, mas o trabalho foi jogado fora). Com fila durável, o request só enfileira e responde 202; o worker processa; o cliente acompanha por WebSocket ou polling. A fila também sobrevive ao restart — o semáforo em memória, não.

  2. Streaming de tokens deixa a resposta do LLM mais rápida?
    ver resposta

    Não a latência total — o modelo gera os mesmos tokens no mesmo tempo. Muda o tempo até o primeiro conteúdo útil: em vez de 10 segundos de spinner, o texto começa em meio segundo. É uma melhoria de latência percebida. O custo: a validação estruturada (Zod) só pode rodar sobre o texto completo, então a UI precisa saber mostrar texto parcial e lidar com um stream que termina inválido ou é cortado no meio.

  3. Quando vale a pena usar URL pré-assinada pra upload em vez de mandar o arquivo pela sua Server Action?
    ver resposta

    Quando o arquivo é grande ou a função é serverless: o corpo inteiro passando pelo seu servidor ocupa memória, conta no limite de corpo (o Gabarita precisou de bodySizeLimit: "25mb") e na duração da função. Com URL pré-assinada, o servidor só assina uma permissão curta e limitada (uma key, um método, um prazo); o navegador manda direto pro bucket. O preço: a validação de tipo e tamanho precisa ir pra assinatura (content-type amarrado) e pra um passo de confirmação depois do upload, porque o servidor não viu os bytes.

  4. O Gabarita não tem pgvector. Ele faz RAG?
    ver resposta

    Faz grounding, não RAG vetorial. fetchStyleReferences recupera questões reais por filtro relacional (especialidade e tema) e as põe no prompt; o resumo de diretriz é ancorado no texto completo da fonte e só sai se a citação existir literalmente nele. Pra esses casos, o critério de recuperação é exato e conhecido, então SQL comum é melhor que similaridade. Embedding passa a valer quando a pergunta é “o que é parecido com isto?” — questões semelhantes à que o aluno errou, por exemplo, que nenhum filtro de tema captura bem.

  5. Como você testaria, sem chamar o Gemini, o fluxo “responder questão → ver explicação” de ponta a ponta?
    ver resposta

    Em dois níveis. Integração (já existe): RTL com a action mockada e fake timers, provando os estados “escrevendo”, “pronto” e o fallback. E2E (falta): Playwright contra o app real com o AIProvider trocado pelo fake via variável de ambiente (hoje getAIProvider() sempre cria o Gemini — seria uma linha a mais na fábrica), ou interceptando a chamada com page.route quando ela parte do navegador. O princípio é o mesmo nos dois: o modelo é uma dependência não determinística e cara, então o teste fixa a saída dele e verifica o que o seu código faz com ela.
